# Задание №4. Новая функциональность: мониторинг акций

## 1. Что добавлено

Выбран вариант «Персональный мониторинг акций»: пользователь добавляет акции в свой список
наблюдения и создаёт ценовые уведомления. Celery периодически проверяет последнюю цену
и один раз отмечает сработавшее уведомление.

## 2. Функциональные требования

| ID | Требование |
|---|---|
| FR-N-01 | Авторизованный пользователь может добавить акцию в личный список наблюдения. |
| FR-N-02 | Повторное добавление той же акции не создаёт вторую запись. |
| FR-N-03 | Пользователь может удалить акцию из своего списка наблюдения. |
| FR-N-04 | Пользователь может создать уведомление: акция, целевая цена, условие «выше или равно» / «ниже или равно». |
| FR-N-05 | Уведомление срабатывает, когда последняя известная цена удовлетворяет условию. |
| FR-N-06 | Срабатывание фиксируется один раз; повторные проверки не меняют время срабатывания. |
| FR-N-07 | Неактивные и уже сработавшие уведомления повторно не проверяются. |
| FR-N-08 | Пользователь видит свои уведомления, их состояние и время срабатывания. |
| FR-N-09 | Список наблюдения и уведомления доступны через REST API; пользователь видит только свои записи. |
| FR-N-10 | Неавторизованный пользователь не имеет доступа к страницам и API мониторинга. |

## 3. Модель данных

Добавлена миграция `dashboard/migrations/0008_pricealert_watchlist.py`.

**Watchlist**
- `user` — владелец, `ForeignKey` на пользователя;
- `share` — акция, `ForeignKey` на `Share`;
- `created_at` — дата добавления;
- ограничение `unique_together = ("user", "share")`.

**PriceAlert**
- `user`, `share` — владелец и акция;
- `target_price` — целевая цена;
- `condition` — `above` или `below`;
- `is_active` — уведомление включено;
- `triggered` — уведомление уже сработало;
- `triggered_at` — время срабатывания;
- `created_at` — дата создания.

## 4. Веб-интерфейс и API

- Страницы: `/watchlist/`, `/watchlist/add/`, `/watchlist/remove/<pk>/`,
  `/alerts/`, `/alerts/add/`, `/alerts/remove/<pk>/`.
- API: `/api/v1/watchlist/`, `/api/v1/alerts/` (DRF ViewSet, только свои записи).
- Фоновая задача: `check_alerts` в `dashboard/tasks.py`, логика — в
  `dashboard/services/alerts.py`, расписание — в `config/celery.py`.

## 5. Проверка

| Проверка | Результат |
|---|---|
| `manage.py check` | ошибок нет |
| `manage.py migrate` | миграция `0008` применяется |
| `manage.py test` | все тесты проходят |
| Повторное добавление в watchlist (веб) | 302, запись одна |
| Повторное добавление в watchlist (API) | 400 |
| Уведомление при цене 160 и цели `>= 150` | `triggered=True`, `triggered_at` заполнен |
| Повторная проверка | `triggered_at` не меняется |
| API под другим пользователем | чужие записи не видны, удаление даёт 404 |
| Неавторизованный доступ | редирект на `/user/login/` |

## 6. Ограничение

Уведомление отображается в интерфейсе и API, но не отправляется во внешние каналы
(email, push). Для учебного проекта этого достаточно; отправка сообщений — отдельная задача.
