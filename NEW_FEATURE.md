# Задание №4. Новая функциональность: персональный мониторинг акций

## 1. Почему выбран этот вариант

Мониторинг опирается на уже существующую модель `Share` и на механизм обновления цен,
не требует внешних сервисов и проверяется локально. Пользователь получает практическую
ценность: свой список наблюдения и уведомления по целевой цене.

## 2. Функциональные требования к новой функциональности

Сформулированы до реализации, по ним же велась проверка.

| ID | Требование |
|---|---|
| FR-N-01 | Авторизованный пользователь может добавить акцию в персональный список наблюдения. |
| FR-N-02 | Повторное добавление той же акции тем же пользователем не создаёт вторую запись. |
| FR-N-03 | Пользователь может удалить акцию из своего списка наблюдения. |
| FR-N-04 | Пользователь может создать ценовое уведомление: акция, целевая цена, условие «выше или равно» / «ниже или равно». |
| FR-N-05 | Уведомление срабатывает, когда последняя известная цена акции удовлетворяет условию. |
| FR-N-06 | Срабатывание фиксируется однократно: повторные проверки не создают повторных срабатываний. |
| FR-N-07 | Неактивные и уже сработавшие уведомления повторно не проверяются. |
| FR-N-08 | Пользователь видит список своих уведомлений и их состояние (активно, сработало, время срабатывания). |
| FR-N-09 | Список наблюдения и уведомления доступны через REST API; каждый пользователь видит только свои записи. |
| FR-N-10 | Неавторизованный пользователь не имеет доступа к страницам и API мониторинга. |

### Критерии приёмки

- Повторный запуск проверки при уже выполненном условии не меняет `triggered_at`.
- При `last_price = None` уведомление не срабатывает и задача не падает.
- API не отдаёт чужие записи и не позволяет создать запись от имени другого пользователя.

## 3. Изменения в модели данных

Миграция `dashboard/migrations/0008_pricealert_watchlist.py`.

**Watchlist** — персональный список наблюдения:

- `user` → `auth.User`, `CASCADE`, `related_name="watchlists"`
- `share` → `Share`, `CASCADE`, `related_name="watchlists"`
- `created_at` — дата добавления
- ограничение `unique_together = ("user", "share")` (закрывает FR-N-02)

**PriceAlert** — целевой уровень цены:

- `user`, `share` — аналогично
- `target_price` — целевая цена
- `condition` — `above` / `below`
- `is_active` — уведомление включено
- `is_triggered` — срабатывание уже зафиксировано
- `triggered_at` — время срабатывания
- `created_at`, сортировка `-created_at`

## 4. Изменения в архитектуре и интерфейсе

- **Веб-слой (CBV):** `WatchlistListView`, `WatchlistCreateView`, `WatchlistDeleteView`,
  `PriceAlertCreateView`, `PriceAlertDeleteView` в `dashboard/views.py`;
  защита `IsUserAuthenticatedMixin`, выборка ограничена `user=request.user`.
- **Маршруты:** `/watchlist/`, `/watchlist/add/`, `/watchlist/delete/<pk>/`,
  `/alerts/`, `/alerts/delete/<pk>/`.
- **Шаблоны:** `watchlist.html`, `watchlist_add.html`, `watchlist_delete.html`,
  `alerts.html`, `alert_delete.html`, ссылки в `base.html`.
- **API (DRF):** `WatchlistViewSet`, `PriceAlertViewSet` в
  `dashboard/api/v1/views_watchlist.py`, сериализаторы в `serializers_watchlist.py`,
  регистрация в `router.py` → `/api/v1/watchlist/`, `/api/v1/alerts/`.
  `IsAuthenticated` + фильтрация `queryset` по `request.user`.
- **Фоновые задачи:** `check_price_alerts` в `dashboard/tasks.py`, расписание
  `check-alerts-every-10-seconds` в `config/celery.py`.
- **Админка:** регистрация `Watchlist` и `PriceAlert`.

## 5. Проверка работоспособности

| Проверка | Результат |
|---|---|
| `manage.py check` | `System check identified no issues (0 silenced).` |
| `manage.py migrate` | `dashboard.0008_pricealert_watchlist ... OK` |
| `manage.py test` | `Ran 10 tests ... OK` (регрессий нет) |
| `runserver`, `GET /` | 200 |
| `GET /api/v1/shares/` | 200 |
| `GET /watchlist/`, `/alerts/` без входа | 302 (редирект на вход) |
| `GET /watchlist/`, `/alerts/` после входа | 200 |
| `GET /api/v1/watchlist/`, `/api/v1/alerts/` после входа | 200, в ответе только записи текущего пользователя |
| Срабатывание уведомления | цена 160 при цели `>= 150` → `is_triggered = True`, `triggered_at` заполнен |
| Повторная проверка при цене 170 | `triggered_at` не изменился — дубля нет |
| Удаление из списка наблюдения | запись удаляется, чужие записи недоступны (404) |

Проверка выполнялась на рабочей БД скриптом, который создаёт пользователя, акцию,
запись наблюдения и уведомление, дважды запускает задачу проверки и обращается к страницам
и API от имени этого пользователя.

## 6. Осознанные ограничения

- Уведомление фиксируется в БД и отображается в интерфейсе/API; отправка во внешние каналы
  (e-mail, push) не реализована — это отдельная задача, выходящая за рамки варианта.
- Проверка использует `Share.last_price`, который обновляет существующая задача
  `update_last_price`; при отсутствии цены уведомление просто не проверяется.
