# Отчет о работе с AI-агентами

## 0. Фактическая схема выполнения

| Проход | Ветка | Исходное состояние | Инструмент |
|---|---|---|---|
| 1 | `opencode` | клон репозитория, коммит `362510b` | OpenCode (агент Big Pickle) |
| 2 | `cline` | отдельная чистая копия, коммит `362510b` | независимый повторный проход, выполненный тем же агентом в режиме «с чистого листа» |

**Важное ограничение.** Второй проход планировалось выполнить в Cline (расширение
`saoudrizwan.claude-dev-4.1.25` найдено в `~/.vscode/extensions`). Cline — GUI-расширение
VSCode без CLI-режима, управлять им из терминала невозможно. Попытки поднять вместо него
Gemini CLI упёрлись в квоты и недоступность моделей (см. п. 3). Поэтому второй проход выполнен
тем же агентом, но в отдельной копии проекта: файлы из ветки `opencode` не копировались,
анализ и правки делались заново. Это ограничение окружения, а не полноценная работа Cline.

## 1. Какие задачи ставились агенту

Задания 1–4 из `HOMEWORK.md`:

1. Анализ исходного кода: назначение, стек, структура, архитектура, зависимости, модель данных,
   механизмы обработки запросов и работы с БД.
2. Восстановление фактически реализованных функциональных требований: нумерованный список
   с подтверждением в коде, бизнес-правила и ограничения, отдельно — дефекты и неоднозначности.
3. Модернизация, устранение дефектов, рефакторинг; обязательный успешный запуск приложения
   без потери функциональности.
4. Реализация одной новой функции. Выбран вариант «Персональный мониторинг акций»:
   список наблюдения, целевые ценовые уровни, уведомления при достижении, без дублей уведомлений.

Дополнительно: аккуратно разделить исправление существующих ошибок и разработку новой
функциональности; проверить результаты, а не принимать на веру.

## 2. Основные промпты

**Проход 1 (`opencode`).** Постановка = текст `HOMEWORK.md` (задания 1–4) плюс уточнения:
выбрать вариант новой функциональности №1 (мониторинг акций), дефекты перечислить отдельно
от требований, результат закоммитить и запушить в ветку `opencode`.

**Проход 2 (`cline`).** Отдельный промпт на 66 строк (сохранён в `CLINE_PROMPT.md`), ключевые
требования:

```
КРИТИЧЕСКИ ВАЖНО:
- Работай ТОЛЬКО в текущей директории проекта
- Анализируй проект ЗАНОВО, не копируй готовые решения
- Выполняй задания по порядку 1->2->3->4
- Все изменения делай в этой копии, закоммить и запушь в текущую ветку cline
...
Описание должно быть именно о реализованном, а не о желаемом. Дефекты не считать требованиями.
...
Результат: работоспособное приложение с модернизированным кодом. Успешный запуск обязателен.
```

## 3. Ошибки и проблемы при работе

| Проблема | Конкретное проявление | Что сделано |
|---|---|---|
| Cline недоступен из терминала | расширение `saoudrizwan.claude-dev-4.1.25` есть в `~/.vscode/extensions`, CLI-режима нет | второй проход выполнен в отдельной копии проекта |
| Квота Gemini | `gemini-3.1-pro`: `You exceeded your current quota ... limit: 0` | перебор моделей через `-m` |
| Модели отключены | `gemini-2.5-flash`, `gemini-2.5-pro`, `gemini-2.5-flash-lite`: `This model ... is no longer available to new users. Please update your code to use models/gemini-3.8-flash` | попытка перейти на предложенные модели |
| Сетевые ошибки | `gemini-flash-latest`: повторяющийся `TypeError: fetch failed sending request` | отказ от Gemini CLI |
| Нет node/npm в PATH | `node: command not found` | ручная распаковка `node-v20.18.1-linux-x64` в `/tmp` (без root) |
| Несовместимость окружения | Python 3.14 + Django 4.1.13 / Celery 5.2.7 | использование подготовленного `.venv` с патчами |
| Сломанный pip в новом venv | `ModuleNotFoundError: No module named 'pip._internal.utils'`, `WARNING: Ignoring invalid distribution ~ip`, Django распаковался без `django/utils` | `get-pip.py` не помог; взят рабочий `.venv` |
| Нет PostgreSQL | приложение не стартовало | переключение `DATABASES` на SQLite (обе ветки) |
| Ошибка генерации шаблонов | `bash: unexpected EOF while looking for matching '"'` в heredoc | команда переписана, файлы созданы отдельно |
| Ошибка в git-операциях | `COMPARISON.md` закоммичен в локальную ветку `cline` (`144c95b`) вместо `opencode`, `git push opencode` вернул `Everything up-to-date` | обнаружено сверкой `git ls-remote`; файл добавлен в `opencode` коммитом `5c18d23`, локальные `cline` и `main` приведены к удалённым |

## 4. Какие корректировки вносились

- Отказ от запуска Gemini CLI и переход к независимому повторному проходу.
- Замена PostgreSQL на SQLite для локального запуска и прогона тестов.
- При восстановлении требований сначала выписывались дефекты отдельным списком, чтобы они
  не попадали в FR (требование задания №2).
- Переписывание `market_data.get_last_data`, `services/graph.get_graph`, `tasks.update_last_price`
  после первой версии: исходный код падал на `None` и игнорировал `nano` у цены.

## 5. Как проверялись результаты

- `python manage.py check` → `System check identified no issues (0 silenced).`
- `python manage.py migrate` → применяются миграции `dashboard.0001`–`0008`.
- `python manage.py test` → `Ran 10 tests ... OK` в обеих ветках.
- Каждое восстановленное требование сверялось с конкретным файлом/классом/функцией.
- Содержимое удалённых веток проверялось независимо от локального состояния:
  `git ls-remote`, `git cat-file -e <sha>:COMPARISON.md`.
- Ветка `cline` получена из чистой копии на `362510b`; файлы `opencode` в неё не переносились.

## 7. Выводы по опыту работы

- Агент устойчиво выполняет длинные многошаговые задачи: анализ → правки → миграции → тесты,
  без потери исходной функциональности.
- Слабые места — окружение: старые зависимости и отсутствие инструментов в PATH требуют
  ручных обходных решений, и агент делает их сам, но с заметным числом итераций.
- Проверка обязательна: часть ошибок (игнорирование `nano`, падение на `None`, коммит не в ту
  ветку) была найдена именно сверкой результата, а не по отчёту агента.
