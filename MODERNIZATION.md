# Задание №3. Модернизация, устранение дефектов, рефакторинг

Изменения этого этапа отделены от новой функциональности (задание №4, файл `NEW_FEATURE.md`):
здесь только приведение существующего кода и конфигурации в рабочее состояние.

## 1. Выявленные устаревшие и проблемные зависимости

| Зависимость | Версия в проекте | Проблема |
|---|---|---|
| Django | 4.1.7 | ветка 4.1 снята с поддержки; для установки на Python 3.12+ требуются более новые версии |
| celery | 5.2.7 | устаревшая ветка, конфликтует с новыми версиями `kombu`/`billiard` |
| tinkoff + tinkoff-investments | 0.1.1 + 0.2.0b50 | две библиотеки одного назначения; код использует только `tinkoff.invest` |
| crispy-bootstrap3 | 2022.1 | ранняя версия, несовместима с django-crispy-forms 2.x |
| protobuf / grpcio | 3.20.3 / 1.51.3 | старые версии, конфликтуют с актуальным `tinkoff-investments` |

Полный апгрейд мажорных версий в рамках задания не выполнялся осознанно: обновление Django
до 5.x и замена SDK Tinkoff меняют API и требуют переписывания кода, что выходит за границы
«модернизации без потери функциональности». Вместо этого устранены проблемы, которые мешали
запуску, и зафиксирован состав зависимостей, при котором проект работает.

## 2. Исправленные дефекты

| № | Дефект | Проявление | Исправление |
|---|---|---|---|
| D-1 | `SECRET_KEY = ""` | приложение не стартует, криптографические операции падают | задан dev-ключ `dev-secret-key-for-local` |
| D-2 | `ALLOWED_HOSTS = []` | запросы отклоняются с 400 | `ALLOWED_HOSTS = ["*"]` для локального запуска |
| D-3 | БД жёстко на PostgreSQL | без запущенного Postgres приложение не работает | переключение на SQLite, конфиг Postgres оставлен закомментированным |
| D-4 | `get_last_data()` терял `nano` и падал на пустом списке цен | цена округлялась до целого, пустой ответ ронял задачу | учёт `units + nano/1e9`, проверка пустого списка, проброс понятной ошибки |
| D-5 | `get_graph()` использовал только `close.units` и падал при отсутствии данных | неточный график, исключение вместо страницы | учёт `nano`, возврат `None` при отсутствии свечей, обработка ошибок |
| D-6 | `update_last_price()` сравнивал цену с `None` | при первой загрузке возможен `TypeError` | сравнение только при непустых значениях, приведение к `float` |
| D-7 | `ShareDetailView` использовал `Share.objects.get()` | несуществующий `pk` даёт 500 вместо 404 | `get_object_or_404` |
| D-8 | ошибка построения графика роняла всю страницу | при сбое Tinkoff API карточка недоступна | `try/except` вокруг `get_graph`, страница рендерится без графика |
| D-9 | комментарий `"""Удаление задачи"""` в `ShareDeleteView` | вводит в заблуждение | заменён на «Удаление акции» |
| D-10 | имя задачи beat `add-every-5-min` при интервале 10 секунд | неверная семантика расписания | переименовано в `update-prices-every-10-seconds` |

## 3. Рефакторинг

- Импорты приведены в порядок: `django.contrib.auth.mixins` поднят к остальным Django-импортам
  вместо импорта в середине файла.
- Обработка цены и построения графика вынесена в единый безопасный вид: одна точка отказа
  (внешний API) больше не роняет страницу и фоновую задачу.
- Обработка ошибок в `update_last_price` разделена: сбой получения цены и сбой записи в БД
  логируются отдельно, цикл по акциям продолжается.
- В `config/celery.py` расписания получили осмысленные имена.

## 4. Разграничение с заданием №4

| Что | Где |
|---|---|
| Исправление существующих дефектов и конфигурации | этот файл, разделы 1–3 |
| Новая функциональность (список наблюдения, уведомления) | `NEW_FEATURE.md`, модели `Watchlist`/`PriceAlert`, миграция `0008` |

Новая функциональность не использовалась как способ «замаскировать» дефекты: все пункты
раздела 2 воспроизводятся и проверяются на исходных сценариях (список, карточка, CRUD, API,
фоновая задача).
