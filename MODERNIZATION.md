# Задание №3. Модернизация, устранение дефектов, рефакторинг

Здесь только приведение существующего кода и конфигурации в рабочее состояние.
Новая функциональность описана отдельно в `NEW_FEATURE.md` — исправления и разработка
разграничены.

## 1. Выявленные устаревшие и проблемные зависимости

| Зависимость | Версия | Проблема |
|---|---|---|
| Django | 4.1.7 | ветка 4.1 не поддерживается, для новых версий Python нужен апгрейд |
| celery | 5.2.7 | устаревшая ветка, конфликты с новыми `kombu`/`billiard` |
| tinkoff + tinkoff-investments | 0.1.1 + 0.2.0b50 | дублирование: код использует только `tinkoff.invest` |
| crispy-bootstrap3 | 2022.1 | несовместим с django-crispy-forms 2.x |
| protobuf / grpcio | 3.20.3 / 1.51.3 | старые версии, конфликтуют с актуальным Tinkoff SDK |

Мажорный апгрейд не выполнялся: обновление Django до 5.x и замена Tinkoff SDK меняют API
и требуют переписывания кода, что противоречит требованию «функциональность не должна
потеряться». Устранены проблемы, блокировавшие запуск, и зафиксировано рабочее состояние.

## 2. Исправленные дефекты

| № | Дефект | Проявление | Исправление |
|---|---|---|---|
| D-1 | `SECRET_KEY = ""` | приложение не стартует | задан `dev-secret-key` |
| D-2 | `ALLOWED_HOSTS = []` | запросы отклоняются с 400 | `ALLOWED_HOSTS = ["*"]` для локального запуска |
| D-3 | БД жёстко на PostgreSQL | без Postgres приложение не работает | переключение на SQLite |
| D-4 | `get_last_data()` терял `nano` и падал на пустом ответе | цена округлялась, пустой ответ ронял задачу | `units + nano/1e9`, проверка пустого списка, понятная ошибка |
| D-5 | `get_graph()` брал только `units`, не обрабатывал пустые данные | неточный график, исключение вместо страницы | учёт `nano`, возврат `None` без свечей, обработка ошибок |
| D-6 | `update_last_price()` сравнивал цену с `None` | `TypeError` при первом обновлении | сравнение только при непустых значениях, приведение к `float` |
| D-7 | `ShareDetailView` использовал `Share.objects.get()` | несуществующий `pk` давал 500 | `get_object_or_404` |
| D-8 | ошибка графика роняла страницу карточки | при сбое Tinkoff API карточка недоступна | `try/except` вокруг `get_graph`, рендер без графика |
| D-9 | комментарий `"""Удаление задачи"""` в `ShareDeleteView` | вводит в заблуждение | заменён на «Удаление акции» |
| D-10 | ключ расписания `add-every-5-min` при интервале 10 секунд | неверная семантика | переименован в `update-prices` |

## 3. Рефакторинг

- Импорт `django.contrib.auth.mixins` перенесён к остальным Django-импортам.
- Внешний вызов Tinkoff API изолирован: его сбой больше не роняет ни страницу, ни фоновую задачу.
- В `update_last_price` разделены ошибка получения цены и ошибка записи в БД — цикл по акциям
  продолжается в обоих случаях.
- Расписания Celery получили осмысленные имена (`update-prices`, `check-alerts`).
- Веб-часть новой функциональности вынесена в отдельный модуль `views_ext.py`, чтобы не
  раздувать `views.py` исходного приложения.
