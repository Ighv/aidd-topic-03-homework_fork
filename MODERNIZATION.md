# Задание №3. Модернизация, исправление дефектов и рефакторинг

## 1. Что было устаревшим или проблемным

| Зависимость / настройка | Проблема | Что сделано |
|---|---|---|
| Django 4.1.7 | старая ветка, не поддерживается | обновлён патч до 4.1.13 |
| `tinkoff` 0.1.1 + `tinkoff-investments` 0.2.0b50 | две библиотеки одного назначения, код использует только `tinkoff.invest` | лишний `tinkoff` убран из `requirements.txt` |
| PostgreSQL в настройках | без запущенного Postgres приложение не стартует | для локального запуска переключено на SQLite |
| `SECRET_KEY = ""` | Django не может подписать сессию/CSRF | задан dev-ключ |
| `ALLOWED_HOSTS = []` | запросы к dev-серверу отклоняются | добавлен `["*"]` для локальной разработки |
| `LOGIN_URL` не задан | `@login_required` отправлял на несуществующий `/accounts/login/` | добавлен `LOGIN_URL = "user:auth"` |

Полный переход на Django 5.x и новую версию Tinkoff SDK не делался: это меняет API и требует
переписывания рабочих сценариев, что выходит за рамки задачи «модернизация без потери функциональности».

## 2. Исправленные дефекты

| № | Дефект | Исправление |
|---|---|---|
| D-1 | `get_last_data()` терял `nano` и падал на пустом ответе | цена считается как `units + nano / 1e9`, пустой ответ обрабатывается |
| D-2 | `get_graph()` использовал только `close.units` и падал без свечей | учитывается `nano`, при отсутствии данных возвращается `None` |
| D-3 | `update_last_price()` сравнивал цену с `None` | сравнение только при непустых значениях, приведение к `float` |
| D-4 | `ShareDetailView` использовал `Share.objects.get()` | заменено на `get_object_or_404()` |
| D-5 | ошибка Tinkoff API роняла страницу акции | `get_graph()` обёрнут в `try/except`, страница открывается без графика |
| D-6 | комментарий «Удаление задачи» в `ShareDeleteView` | заменён на «Удаление акции» |
| D-7 | ключ расписания `add-every-5-min` при интервале 10 секунд | переименован в `update-prices` |
| D-8 | повторное добавление акции в watchlist давало 500 | используется `get_or_create`, API возвращает 400 |
| D-9 | ссылки мониторинга были после `</html>` | перенесены в footer |
| D-10 | URL пользователя был `/userlogin/` из-за `path("user", ...)` | добавлен слеш, теперь `/user/login/` |

## 3. Рефакторинг

- Проверка уведомлений вынесена из Celery-задачи в `dashboard/services/alerts.py`.
  Задача `check_alerts` теперь только вызывает сервис — логику можно тестировать без Celery.
- Убраны дублирующиеся импорты и лишние импорты в `urls.py` и `views_ext.py`.
- API-сериализаторы watchlist/alerts приведены к обычному виду: прямой импорт `Share`,
  валидация дублей и целевой цены.
- В `admin.py` зарегистрированы `Watchlist` и `PriceAlert`.
